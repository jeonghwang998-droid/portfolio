Skin AI

얼굴 피부 사진 한 장으로 11종 피부질환을 분류하고, AI가 임상 소견까지 설명해주는 학습용 진단 보조 플랫폼.

⚠ 의료 면책 — 교육·연구 목적의 보조 도구이며, 확정 진단은 피부과 전문의 대면 진료로만 가능합니다.
개요 아키텍처 AI 파이프라인 제한사항 학습 데이터 회고
01

개요

피부과 전공의·의대생이 AI 분류 결과와 실제 진단을 비교하며 학습할 수 있도록 만든 서비스입니다. 사진을 올리면 DenseNet121 / EfficientNet-B3가 질환을 분류하고, Grad-CAM으로 판단 근거를 시각화하고, Claude가 임상 리포트를 자연어로 생성합니다.

  • 분류 대상 11종 — 건선, 아토피피부염, 여드름, 광선각화증, 기저세포암, 멜라닌세포모반, 악성흑색종, 지루각화증, 편평세포암, 피부섬유종, 혈관종
  • 핵심 기능 — 이미지 분류 + Grad-CAM 히트맵 + LLM 임상 리포트 + 멀티턴 채팅 + 분석 이력 관리

WHY — OOD 필터를 넣은 이유

DenseNet은 입력을 반드시 11종 중 하나로 분류하는 폐쇄형 분류기라, 강아지 사진도 아토피피부염 86% 신뢰도로 오분류했습니다. 신뢰도 임계값·엔트로피 같은 일반적인 방법이 모두 실패해서, 추론 전 Claude Haiku vision으로 "피부 이미지인가"를 먼저 판별하도록 했습니다. 추가 레이턴시는 500~900ms.

07

회고

ROLE — 역할
Frontend Leader + Backend / DB 커버
  • 프론트엔드 팀 리드 — UI/UX 설계 및 구현 총괄
  • JS 로직 구축 — 클라이언트 상태 관리, 서버 통신, 인터랙션 구현
  • cover백엔드 서버 구축 — Node.js/Express API 설계 및 구현
  • cover데이터베이스 설계 및 구축 — Supabase(PostgreSQL) 스키마 설계·구현, 이미지 Storage 구조 설계
PROBLEM — 문제
운영·유지보수 및 하드코딩 문제
  • 팀원들이 값을 코드에 직접 박아 넣는 하드코딩이 많아, 설정 하나 바꾸려 해도 코드 전체를 뒤져야 했음
  • 환경별로 바뀌는 값들이 상수/설정으로 분리돼 있지 않아 운영 중 값 변경 및 유지보수가 번거로움
  • API 명세서 없이 개발 — 엔드포인트 위치·스펙이 문서화돼 있지 않아 협업 중 혼선 발생
  • 데이터베이스 권한 부여가 제대로 안 돼 있어 접근 범위 관련 이슈 발생
SOLUTION — 해결
상수 분리 및 문서화로 정리
  • 코드 곳곳에 흩어져 있던 하드코딩 값을 constants 파일로 전부 이관 — 값 하나 바꿀 때 코드 전체를 뒤지지 않고 한 곳만 수정하면 되도록 개선
  • 환경별로 달라지는 값은 .env 설정으로 분리해 운영/개발 환경 전환 시 코드 수정 없이 값만 교체되도록 구성
  • API 문서화 시작 — 엔드포인트·요청/응답 형식을 정리해 팀원들이 코드를 뒤지지 않고도 API 스펙을 바로 확인할 수 있도록 함
  • 데이터베이스 권한을 역할(전공의/학생/관리자)별로 재설계해 필요한 범위까지만 접근 가능하도록 재정비
RESULT — 결과
교내 경진대회 최우수상 (1위)
  • 상수 분리·문서화로 유지보수를 훨씬 신중하고 체계적으로 진행할 수 있게 됨
  • API 명세서·데이터 출처까지 정리하면서 프로젝트 전체 완성도가 한 단계 올라감
  • 이슈 체크 전후를 비교해보니 반복 작업에 들던 노력과 시간이 눈에 띄게 줄어든 걸 확인 — 이후 진행한 프로젝트에도 이 방식을 적용해 계속 좋은 효율을 얻으며 한 단계 더 성장함
  • 팀원들과 함께 문제를 하나씩 개선해나간 결과, 교내 경진대회에서 최우수상(1등) 수상
